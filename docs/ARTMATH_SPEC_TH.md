# ข้อกำหนด ArtMath สำหรับงานบนคลาวด์

เอกสารนี้สรุปพฤติกรรมของโค้ดใน repository ปัจจุบันและเกณฑ์ส่งมอบงานสำหรับใช้จากมือถือ อ่านร่วมกับ [README](../README.md) และ [คู่มือมือถือ](MOBILE_WORKFLOW_TH.md) ข้อความ “ผ่าน” ในเอกสารส่งต่อเก่าไม่ใช่ผลตรวจของโค้ดหรือไฟล์ตอนใหม่

## 1. แหล่งข้อมูลและขอบเขต

| ข้อมูล | ตำแหน่งถาวร | การใช้งาน |
|---|---|---|
| โค้ด คำสั่งหลัก คู่มือ และแม่แบบว่าง | GitHub | ระบุ branch/commit ที่ใช้ทุกครั้ง |
| ฟุตเทจ เสียง บท ไทม์ไลน์ และสถานะตอนจริง | Drive หรือพื้นที่ส่วนตัวที่ผู้ใช้เลือก | โหลดเฉพาะไฟล์ที่ต้องใช้ในตอนนั้น |
| ไฟล์ที่ใช้ประมวลผล | `.local/episodes/<episode>/` ใน workspace คลาวด์ | เป็นสำเนาทำงาน ไม่ใช่ที่เก็บถาวร |
| MP4 ซับ QA และบันทึกส่งต่อ | พื้นที่ส่วนตัวที่เปิดอ่านกลับได้ | ตรวจการบันทึกสำเร็จก่อนรายงานว่าส่งมอบแล้ว |

Repository นี้เป็นพื้นที่สำหรับโค้ดและเอกสารทั่วไป ไม่ย้ายชุด ArtMath ทั้งโฟลเดอร์เข้ามา: แม้ `.gitignore` กันไฟล์สื่อ แต่ Markdown/JSON ส่วนตัวอาจยังถูก commit ได้ ต้องตรวจรายการ staged files ก่อนส่งทุกครั้ง ใช้แม่แบบส่งต่อใน repository เป็นแม่แบบว่างเท่านั้น

ตัวเรนเดอร์ทำงานกับไฟล์ใน workspace ไม่มีการเชื่อม Drive ดาวน์โหลด/อัปโหลด โคลนเสียง หรือเผยแพร่คลิปในตัว การเข้าถึง Drive ในแชตหนึ่งไม่ยืนยันสิทธิ์ของ environment อีกเครื่องหนึ่ง ตรวจความสามารถที่ใช้ได้ในงานนั้นจริง หากยังรับหรือส่งไฟล์ไม่ได้ ให้บันทึกสิ่งที่ขาดและส่งมอบงานส่วนที่ทำได้ โดยไม่อ้างว่าไฟล์ถูกเก็บใน Drive แล้ว

## 2. กระบวนการต่อหนึ่งตอน

1. อ่านคำสั่งล่าสุด สเปกนี้ และบันทึกส่งต่อของตอนจากพื้นที่ส่วนตัว ตรวจ commit โค้ดและรายการวัตถุดิบที่ใช้
2. ตรวจไฟล์จริงด้วย FFprobe และเปิดดู/ฟังช่วงที่เกี่ยวข้อง บันทึกชื่อไฟล์และ source in/out ของเหตุการณ์ที่นำมาเล่า แยกสิ่งที่เห็นออกจากข้อสันนิษฐาน
3. จัด brief และบทตามโจทย์ตอนนั้น เลือกช็อตที่รองรับเนื้อหา ไม่ใช้ชื่อไฟล์หรือแผนเก่าเป็นหลักฐานว่าเหตุการณ์เกิดขึ้นจริง
4. เตรียมเสียงฉบับสุดท้ายก่อนจับเวลาซับ หากต้องตัดช่องเงียบ ให้ทำขั้นนี้ครั้งเดียวแล้วใช้ไฟล์เดียวเป็นฐานเวลาของภาพและซับ
5. เติม `project.json` และ `timeline.json` ตรวจด้วย `validate` แก้ errors และพิจารณา warnings จากนั้นเรนเดอร์
6. ตรวจ MP4 ที่ส่งออกจริง เปิดดูซับ/crop และฟังเสียงทั้งคลิป เก็บผลตรวจที่ทำจริง ไม่เติมผลที่ยังไม่ได้วัด
7. เก็บผลลัพธ์และบันทึกส่งต่อในพื้นที่ส่วนตัว พร้อมยืนยันว่าอ่านกลับได้ ส่งการเปลี่ยนโค้ดผ่าน PR แยกจากสื่อและสถานะตอน

แนวเล่าเรื่องจากชุด ArtMath ใช้ฮุก ตั้งบริบท ยกระดับเหตุการณ์ และจุดจบที่สัมพันธ์กับภาพเป็นแนวทางสร้างสรรค์ ส่วนความยาวคลิป บุคลิกเสียง และจังหวะเฉพาะตอนยึด brief ล่าสุดของผู้ใช้ ไม่บังคับความยาวเดิมทุกตอนด้วยการเร่งภาพหรือทำซ้ำฟุตเทจเพื่อเติมเวลา

## 3. ภาพ เสียง และซับ

| รายการ | ข้อกำหนดปัจจุบัน |
|---|---|
| ไฟล์ส่งออก | MP4, H.264, yuv420p, 1080×1920, 30 fps และมีเสียง |
| พื้นที่ภาพกลาง | 1080×1264 ที่ y=332 ถึงก่อน 1596; crop แบบ `cover` |
| กรอบแบรนด์ | PNG 1080×1920 ที่อ่านได้จริง; ตรวจขนาดก่อนเรนเดอร์ |
| ฟอนต์ | ฟอนต์ไทยที่โหลดได้ในโครงงาน; ตรวจสระและวรรณยุกต์บนภาพส่งออก |
| ซับเริ่มต้น | จุดศูนย์กลาง y=1296 ขนาดตั้งต้น 82; ซับ ASS มีการปรับขนาดตามข้อความ |
| เพลง | ไม่บังคับ; หากระบุไฟล์เพลง ต้องมีไฟล์และมี audio stream |
| เสียงที่มิกซ์แล้ว | `approved_audio` ใช้แทนเสียงพูดและเพลง ระบบตรวจไฟล์นี้และเข้ารหัส AAC สำหรับ MP4 |
| การตัดช่องเงียบ | ทำก่อนจับเวลาซับ; `trim_voice_silences` ต้องเป็น `false` ใน timeline |

ตัวเรนเดอร์มีฟิลเตอร์ปรับความดัง แต่ผล preflight ไม่ใช่ผลวัด LUFS/true peak ของ MP4 ส่งออก หาก brief กำหนดค่าความดัง ต้องวัดแยกและลงผลใน handoff เสียงที่มิกซ์แล้วผ่าน `approved_audio` จะไม่ถูกมิกซ์หรือปรับความดังซ้ำ

การแสดงผลที่อ่านได้และเหตุการณ์ที่ตรงกับบทต้องตรวจโดยดู/ฟังจริง การตรวจทางเทคนิคไม่ยืนยันข้อเท็จจริงของเรื่องหรือคุณภาพการพากย์

## 4. สัญญาข้อมูลที่ต้องตรงกัน

`project.json` ชี้ source, voice หรือ approved_audio, brand, font และ timeline ด้วย path ภายในโครงงาน ส่วน `output_name` เป็นชื่อ `.mp4` แบบเรียบง่าย ไม่มี path แฝง ดูตัวอย่างที่ใช้ได้ใน README

- `duration` เป็นความยาวคลิป รับ `target_duration` เป็นชื่อทางเลือก; หากระบุทั้งคู่ต้องตรงกัน
- เวลาแต่ละ shot ต้องมี `end > start >= 0`, `duration = end - start` และต่อกันโดยไม่มี gap/overlap
- `frames = round(end × 30) - round(start × 30)`; ผลรวมเท่าจำนวนเฟรมของคลิป
- `playback_speed = (source_out - source_in) / duration` และต้องเป็นค่าบวก รับ `speed` เป็นชื่อทางเลือก; ค่าที่ประกาศขัดกันเป็น error
- `source_in` ต้องไม่ติดลบ และ source interval ต้องไม่เกินไฟล์ต้นฉบับ ภาพต้องมี video stream
- `crop` เป็น `[x, y, width, height]` จำนวนเต็มภายในขอบเขตวิดีโอ หากไม่ระบุ ใช้เต็มภาพต้นฉบับก่อน crop แบบ cover
- shot ID ต้องไม่ซ้ำ ใช้ตัวอักษรละติน ตัวเลข `_` หรือ `-`; zoom อยู่ระหว่าง 1 ถึง 4
- caption ต้องมี string `text` และเวลาเริ่ม/จบที่อยู่ในคลิป ไม่ซ้อน caption ก่อนหน้า
- highlight `text` ต้องปรากฏใน caption และช่วงเวลาอยู่ภายใน caption รับ `word` เป็นชื่อทางเลือก
- ระบบคำนวณฟิลด์ที่ขาดได้เมื่อมีข้อมูลเพียงพอ แต่ไม่ใช้การคำนวณแทนการตรวจฟุตเทจหรือเสียงจริง

`story_editor.py` ใช้ schema สำหรับวางเรื่องและ rough cut แยกต่างหาก ผลจากเครื่องมือนี้ไม่ใช่ timeline ที่ป้อน renderer ได้โดยตรง

## 5. เกณฑ์ตรวจและสถานะส่งมอบ

| ผล | ตัวอย่าง | การดำเนินการ |
|---|---|---|
| Error | JSON/ชนิดข้อมูลผิด, ฟิลด์ที่คำนวณไม่ได้ขาด, เวลา/เฟรม/ความเร็วขัดกัน, source/crop เกินขอบเขต, ซับผิดเวลา, ฟอนต์/กรอบ/สื่อหาย | แก้ก่อนเรนเดอร์; `validate` คืน exit code 2 |
| Warning | shot ยาวกว่า 2.2 วินาที, ซับนอกช่วงแนะนำ 8–22 Unicode characters, คำลงท้ายที่ต้องตรวจบริบท, เสียงจบก่อนคลิป | ดู/ฟังและบันทึกการตัดสินใจ ไม่จำเป็นต้องตัดหรือแก้ทุก warning |
| Preflight ผ่าน | รายงาน `ok=true`, ไม่มี errors | เริ่มเรนเดอร์ได้; ยังไม่เท่ากับตรวจ MP4 สำเร็จ |
| เรนเดอร์ล้มเหลว | FFmpeg หรือการตรวจไฟล์ส่งออกผิดพลาด | exit code 1 และรักษา MP4/ซับเดิม |
| พร้อมส่งมอบ | เรนเดอร์สำเร็จ ตรวจภาพ/เสียงแล้ว และเก็บผลลัพธ์อ่านกลับได้ | บันทึกหลักฐานและงานถัดไปใน handoff |

`QA_preflight.json` มี `ok`, `errors`, `warnings`, `stats` และแสดงการตรวจครั้งล่าสุด `validate` เขียนรายงานอย่างเดียว ไม่สร้างซับหรือวิดีโอ `--force` ไม่ข้าม errors

`render --overwrite` สร้างผลลัพธ์ใน staging แล้วตรวจ MP4 ก่อนแทนที่ไฟล์เป้าหมาย ไม่ลบวิดีโอเดิมล่วงหน้า การแพ็ก ZIP ที่เกิน 50 MiB เป็นการรวมไฟล์ส่งมอบ ไม่รับประกันว่าขนาดจะต่ำกว่า 50 MiB

ใช้ [แม่แบบ HANDOFF](../templates/HANDOFF_TH.md) ในพื้นที่ส่วนตัว บันทึก `not_run`, `passed`, `failed` หรือ `blocked` ให้ตรงกับผลจริง สถานะเหล่านี้เป็นธรรมเนียมส่งต่อของทีม ไม่ใช่ฟิลด์ที่ renderer จัดการให้อัตโนมัติ
